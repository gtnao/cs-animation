## 連結性DP (Profile DP) とは

連結性DP (Profile DP, Broken Profile DP) は、グリッド上の組合せ問題を**列ごとのプロファイル** (境界の状態) を使って解く動的計画法の手法である。ドミノタイリング、ハミルトンパスなどのグリッド問題で広く用いられる。

### プロファイルとは

グリッドを左から右 (または上から下) に列ごとに処理する際、現在の列と次の列の境界における状態を**プロファイル**と呼ぶ。プロファイルはビットマスクやより複雑なデータ構造で表現される。

## 典型問題: ドミノタイリング

### 問題

$M \times N$ のグリッドを $1 \times 2$ のドミノで隙間なく敷き詰める方法の数を求めよ。

### DP の設計

グリッドを左から右に列ごとに処理する。プロファイルは $M$ ビットのビットマスクで、各ビットは「その行のセルが前の列からの横向きドミノで既に埋まっているか」を表す。

- ビット $i$ が 1: 行 $i$ のセルは既に横向きドミノの右半分で埋まっている
- ビット $i$ が 0: 行 $i$ のセルはまだ空いている

### 遷移

列 $c$ を処理するとき、入力プロファイル (前の列からの状態) から出力プロファイル (次の列への状態) を生成する。

各行を上から順に処理し、空いているセルには以下の選択肢がある:

1. **横向きドミノ**: 右隣のセル (列 $c+1$) に伸ばす → 出力プロファイルのそのビットを 1 にする
2. **縦向きドミノ**: 下のセル (行 $i+1$) と一緒に埋める → 2行分を処理

### 実装

```python title="profile_dp.py"
def domino_tiling(M: int, N: int) -> int:
    # dp[profile] = number of ways
    dp = {0: 1}

    for col in range(N):
        new_dp = {}

        for profile, ways in dp.items():
            # Fill column col given incoming profile
            fill(0, profile, 0, M, col, N, ways, new_dp)

        dp = new_dp

    return dp.get(0, 0)

def fill(row, in_profile, out_profile, M, col, N, ways, new_dp):
    if row == M:
        new_dp[out_profile] = new_dp.get(out_profile, 0) + ways
        return

    if (in_profile >> row) & 1:
        # Cell already filled by horizontal domino from previous column
        fill(row + 1, in_profile, out_profile, M, col, N, ways, new_dp)
        return

    # Option 1: Horizontal domino (extends to next column)
    if col + 1 < N:
        fill(row + 1, in_profile, out_profile | (1 << row),
             M, col, N, ways, new_dp)

    # Option 2: Vertical domino (covers current and next row)
    if row + 1 < M and not ((in_profile >> (row + 1)) & 1):
        fill(row + 2, in_profile, out_profile,
             M, col, N, ways, new_dp)
```

## 計算量

| 項目 | 値 |
|------|------|
| 状態数 | $O(2^M)$ (プロファイルの種類) |
| 各列の遷移 | $O(2^M)$ |
| 全体 | $O(N \cdot 2^M \cdot \text{遷移コスト})$ |

$M$ が小さい (通常 $M \leq 20$ 程度) 場合に実用的。$M$ と $N$ のうち小さい方を行数にすることで効率化できる。

## 具体例

$3 \times 4$ のグリッドのドミノタイリング数は 11 通り。

プロファイルの遷移の例:

列0のプロファイル `000` (全て空き) から:
- 行0-1に縦ドミノ、行2に横ドミノ → 出力プロファイル `100`
- 行0に横ドミノ、行1-2に縦ドミノ → 出力プロファイル `001`
- 全行に横ドミノ → 出力プロファイル `111`

## 拡張: ハミルトンパス

グリッド上のハミルトンパス (全てのセルをちょうど1度ずつ通る経路) を数える場合、プロファイルにはセルの接続情報も必要になる。

プロファイルに「どのセルがどのセルとつながっているか」を持たせる必要がある。これは**括弧列**や**union-find 構造**のビットマスクエンコーディングで表現する。

## 拡張: 連結性の管理

プロファイルに連結性情報を追加する場合:

- 各セグメントにラベルを付け、同じラベルは同じ連結成分
- プロファイルは $M$ 個のラベルの列として表現
- ラベルの正規化 (カタラン数的な列挙)

この場合、状態数は $O(B_M)$ (ベル数) 程度に増える。

## 最適化テクニック

### ビットマスクの圧縮

実際に到達可能なプロファイルは全 $2^M$ 通りのうちの一部だけなので、ハッシュマップを使って疎に管理する。

### 行と列の交換

$M > N$ の場合、グリッドを転置して $M$ と $N$ を入れ替えると効率が上がる ($2^M$ が $2^N$ に減る)。

### 遷移のメモ化

同じプロファイルからの遷移は同じ結果になるので、遷移表を事前計算してキャッシュできる。

## 応用

- ドミノタイリング (本記事の主例)
- ポリオミノの数え上げ
- ハミルトンパス・ハミルトン回路
- 独立集合の数え上げ
- 電気回路の接続パターン

## まとめ

| 項目 | 内容 |
|------|------|
| 入力 | $M \times N$ のグリッドと配置ルール |
| 出力 | 条件を満たす配置の数 |
| 時間計算量 | $O(N \cdot 2^M)$ (ドミノタイリングの場合) |
| 空間計算量 | $O(2^M)$ |
| 核心 | 列境界の状態をビットマスクで管理し、列ごとに遷移 |

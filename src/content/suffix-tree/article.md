## Suffix Tree とは

Suffix Tree (接尾辞木) は、文字列 $S$ の全ての接尾辞を格納した圧縮トライ (Patricia Trie) である。1973年に Weiner によって最初に提案され、1976年に McCreight、1995年に Ukkonen がそれぞれ線形時間構築アルゴリズムを発表した。

### 定義

文字列 $S$ (末尾に番兵文字 $\$$ を付加) の Suffix Tree は以下の性質を持つ根付き木である。

1. 内部ノードの子は 2 つ以上
2. 各辺には $S$ の空でない部分文字列がラベルとして付与される
3. 同じノードから出る辺のラベルは異なる文字で始まる
4. 根から各葉へのパス上のラベルを連結すると、$S$ のある接尾辞になる
5. $n$ 個の葉が $n$ 個の接尾辞に1対1対応する

### 空間計算量

Suffix Tree のノード数は $O(n)$、辺の数も $O(n)$ である (内部ノードの子が2つ以上なので、内部ノード数は葉の数 $-1$ 以下)。

辺のラベルを部分文字列の開始位置と長さで表現すれば、全体で $O(n)$ の空間に収まる。

## 構築アルゴリズム

### 素朴な方法: $O(n^2)$

各接尾辞を順に Trie に挿入する。挿入のたびに既存の辺との共通接頭辞を見つけ、必要に応じて辺を分割する。

### Ukkonen のアルゴリズム: $O(n)$

Ukkonen のアルゴリズムはオンラインで Suffix Tree を構築する。文字列の各文字を左から右に読み、以下の3つの規則を適用する。

1. **Rule 1 (延長規則):** 葉の辺を延長する
2. **Rule 2 (分岐規則):** 内部ノードで分岐して新しい葉を作る
3. **Rule 3 (何もしない):** すでに遷移が存在する場合、何もしない

さらに以下の高速化技法を使う。

- **Suffix Link:** 内部ノード $v$ が文字列 $x\alpha$ に対応するとき、$\alpha$ に対応するノードへのリンク
- **Skip/Count trick:** 辺のラベルを飛ばして高速に移動
- **Global end:** 全葉の末端を共有して Rule 1 を $O(1)$ にする

## Suffix Tree と Suffix Array の関係

Suffix Tree の葉を辞書順に読むと Suffix Array が得られる。逆に、Suffix Array と LCP Array から Suffix Tree を $O(n)$ で構築できる。

## 応用

### パターン検索

パターン $P$ を Suffix Tree 上で辿れば $O(|P|)$ で存在判定ができる。出現位置の列挙は追加で $O(k)$ ($k$ は出現回数)。

### 最長共通部分文字列

2つの文字列 $S_1$ と $S_2$ を $S_1\$_1 S_2\$_2$ と連結して Suffix Tree を構築し、両方の文字列からの葉を子孫に持つ最も深い内部ノードが最長共通部分文字列に対応する。

### 最長回文部分文字列

$S$ と $S$ の逆転 $S^R$ の Suffix Tree を合成して求められる。

### その他

- 文字列の周期検出
- 最長反復部分文字列
- 部分文字列の出現回数計数

## 計算量

| 項目 | 内容 |
|------|------|
| 構築 (素朴) | $O(n^2)$ |
| 構築 (Ukkonen) | $O(n)$ |
| 空間 | $O(n)$ |
| パターン検索 | $O(\|P\| + k)$ |
| ノード数 | $O(n)$ |

## まとめ

| 項目 | 内容 |
|------|------|
| 入力 | 長さ $n$ の文字列 $S$ |
| 出力 | $S$ の全接尾辞を表す圧縮トライ |
| 構築時間 | $O(n)$ (Ukkonen) |
| 空間計算量 | $O(n)$ (定数が大きい) |
| 核心 | Suffix Link と延長規則による効率的な構築 |
